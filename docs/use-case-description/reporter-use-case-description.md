# Use Case Description — ผู้แจ้งเหตุ (Reporter)

---

## ตารางที่ 1 สมัครสมาชิก (Register)

| | |
|:---|:---|
| **Use case name:** | สมัครสมาชิก (Register) |
| **Description:** | ผู้แจ้งเหตุสามารถสร้างบัญชีผู้ใช้ใหม่ในระบบ โดยกรอกข้อมูลส่วนตัว เช่น อีเมล ชื่อ-นามสกุล เบอร์โทรศัพท์ และรหัสผ่าน เพื่อใช้งานระบบแจ้งเหตุฉุกเฉิน |
| **Primary Actors:** | ผู้แจ้งเหตุ (Reporter) |
| **Goals:** | ผู้แจ้งเหตุมีบัญชีในระบบและสามารถเข้าสู่ระบบเพื่อใช้งานได้ |
| **Precondition:** | ผู้แจ้งเหตุยังไม่มีบัญชีในระบบ ระบบพร้อมใช้งาน |
| **Postcondition:** | บัญชีผู้แจ้งเหตุถูกสร้างในฐานข้อมูล ระบบออก JWT Token ให้ และเข้าสู่ระบบอัตโนมัติ |
| **Invariants:** | อีเมลต้องไม่ซ้ำกับบัญชีอื่นในระบบ รหัสผ่านถูกเข้ารหัสด้วย bcrypt ก่อนบันทึก |
| **Scenarios:** | 1. ผู้แจ้งเหตุเปิดหน้าสมัครสมาชิก |
| | 2. ระบบแสดงแบบฟอร์มสมัครสมาชิก |
| | 3. ผู้แจ้งเหตุกรอก อีเมล, ชื่อ-นามสกุล, เบอร์โทร, รหัสผ่าน และยืนยันรหัสผ่าน |
| | 4. ผู้แจ้งเหตุกดปุ่ม "สมัครสมาชิก" |
| | 5. ระบบตรวจสอบความถูกต้องของข้อมูล |
| | 6. ระบบเข้ารหัสรหัสผ่านและบันทึกข้อมูลลงฐานข้อมูล |
| | 7. ระบบสร้าง JWT Token และเข้าสู่ระบบอัตโนมัติ |
| | 8. ระบบแสดงหน้าหลักของผู้แจ้งเหตุ |
| **Alternative:** | **กรณีข้อมูลไม่ถูกต้อง** |
| | 1. หากกรอกข้อมูลผิดรูปแบบหรือไม่ครบ |
| | 2. ระบบแสดงข้อความแจ้งเตือน |
| | 3. ผู้แจ้งเหตุแก้ไขข้อมูล |
| | 4. ระบบกลับไปขั้นตอนตรวจสอบข้อมูลใหม่ |
| | **กรณีอีเมลซ้ำ** |
| | 1. หากอีเมลที่กรอกมีอยู่ในระบบแล้ว |
| | 2. ระบบแสดงข้อความ "อีเมลนี้ถูกใช้งานไปแล้ว" |
| | 3. ผู้แจ้งเหตุเปลี่ยนอีเมลและลองใหม่ |

## ตารางที่ 2 เข้าสู่ระบบ (Login)

| | |
|:---|:---|
| **Use case name:** | เข้าสู่ระบบ (Login) |
| **Description:** | ผู้แจ้งเหตุสามารถเข้าสู่ระบบด้วยอีเมลและรหัสผ่านที่สมัครไว้ เพื่อใช้งานฟีเจอร์ต่างๆ ของระบบ |
| **Primary Actors:** | ผู้แจ้งเหตุ (Reporter) |
| **Goals:** | ผู้แจ้งเหตุเข้าสู่ระบบสำเร็จและสามารถใช้งานระบบได้ |
| **Precondition:** | ผู้แจ้งเหตุมีบัญชีในระบบ บัญชีไม่ถูกระงับ (Block) ระบบพร้อมใช้งาน |
| **Postcondition:** | ผู้แจ้งเหตุได้รับ JWT Token และเข้าสู่หน้าหลักของระบบ |
| **Invariants:** | รหัสผ่านต้องตรงกับที่เข้ารหัสไว้ในฐานข้อมูล Token ถูกเก็บใน httpOnly Cookie |
| **Scenarios:** | 1. ผู้แจ้งเหตุเปิดหน้าเข้าสู่ระบบ |
| | 2. ระบบแสดงแบบฟอร์มเข้าสู่ระบบ |
| | 3. ผู้แจ้งเหตุกรอกอีเมลและรหัสผ่าน |
| | 4. ผู้แจ้งเหตุกดปุ่ม "เข้าสู่ระบบ" |
| | 5. ระบบตรวจสอบอีเมลและรหัสผ่าน |
| | 6. ระบบสร้าง JWT Token และเก็บใน Cookie |
| | 7. ระบบแสดงหน้าหลักของผู้แจ้งเหตุ |
| **Alternative:** | **กรณีอีเมลหรือรหัสผ่านไม่ถูกต้อง** |
| | 1. ระบบแสดงข้อความแจ้งเตือนว่าข้อมูลไม่ถูกต้อง |
| | 2. ผู้แจ้งเหตุกรอกข้อมูลใหม่ |
| | **กรณีบัญชีถูกระงับ** |
| | 1. ระบบแสดงข้อความว่าบัญชีถูกระงับ |
| | 2. ผู้แจ้งเหตุไม่สามารถเข้าสู่ระบบได้ |

## ตารางที่ 3 จัดการข้อมูลส่วนตัว (Manage Profile)

| | |
|:---|:---|
| **Use case name:** | จัดการข้อมูลส่วนตัว (Manage Profile) |
| **Description:** | ผู้แจ้งเหตุสามารถแก้ไขข้อมูลส่วนตัวได้ เช่น ชื่อ-นามสกุล เบอร์โทร และรหัสผ่าน |
| **Primary Actors:** | ผู้แจ้งเหตุ (Reporter) |
| **Goals:** | การแก้ไขข้อมูลส่วนตัวสามารถแก้ไขได้ตามความต้องการของผู้แจ้งเหตุ |
| **Precondition:** | ผู้แจ้งเหตุต้องเข้าสู่ระบบสำเร็จแล้ว ระบบฐานข้อมูลต้องพร้อมใช้งาน |
| **Postcondition:** | ข้อมูลส่วนตัวของผู้แจ้งเหตุถูกอัปเดตในฐานข้อมูล ระบบแสดงข้อมูลที่แก้ไขแล้วอย่างถูกต้อง ระบบบันทึกข้อมูลล่าสุดแทนข้อมูลเดิม |
| **Invariants:** | อีเมลต้องไม่เปลี่ยนแปลง รูปแบบข้อมูลต้องถูกต้องเสมอ (เช่น เบอร์โทรต้องอยู่ในรูปแบบที่ถูกต้อง) ผู้แจ้งเหตุสามารถแก้ไขได้เฉพาะข้อมูลของตนเองเท่านั้น |
| **Scenarios:** | 1. ผู้แจ้งเหตุเข้าสู่ระบบ |
| | 2. ผู้แจ้งเหตุเลือกเมนู "ข้อมูลส่วนตัว" |
| | 3. ระบบแสดงข้อมูลปัจจุบันในแบบฟอร์ม |
| | 4. ผู้แจ้งเหตุแก้ไขข้อมูลที่ต้องการ |
| | 5. ผู้แจ้งเหตุกดปุ่ม "บันทึก" |
| | 6. ระบบบันทึกข้อมูลลงฐานข้อมูล |
| | 7. ระบบแสดงข้อความ "อัปเดตข้อมูลสำเร็จ" |
| **Alternative:** | **กรณีข้อมูลไม่ถูกต้อง** |
| | 1. หากกรอกข้อมูลผิดรูปแบบหรือไม่ครบ |
| | 2. ระบบแสดงข้อความแจ้งเตือน |
| | 3. ผู้แจ้งเหตุแก้ไขข้อมูล |
| | 4. ระบบกลับไปขั้นตอนการบันทึกใหม่ |

## ตารางที่ 4 ปักหมุดแจ้งเหตุฉุกเฉิน (Create Incident Report)

| | |
|:---|:---|
| **Use case name:** | ปักหมุดแจ้งเหตุฉุกเฉิน (Create Incident Report) |
| **Description:** | ผู้แจ้งเหตุสามารถแจ้งเหตุฉุกเฉินโดยเลือกประเภทเหตุการณ์ กรอกรายละเอียด และระบุเบอร์ติดต่อ ระบบจะดึงตำแหน่ง GPS อัตโนมัติเพื่อปักหมุดบนแผนที่ |
| **Primary Actors:** | ผู้แจ้งเหตุ (Reporter) |
| **Goals:** | รายการแจ้งเหตุถูกสร้างสำเร็จและแสดงบนระบบเพื่อให้พนักงานรับเรื่อง |
| **Precondition:** | ผู้แจ้งเหตุต้องเข้าสู่ระบบสำเร็จแล้ว Browser อนุญาตการเข้าถึงตำแหน่ง (Geolocation) มีประเภทเหตุฉุกเฉินอย่างน้อย 1 รายการที่เปิดใช้งานอยู่ |
| **Postcondition:** | รายการแจ้งเหตุถูกบันทึกในฐานข้อมูล สถานะ = REPORTED พร้อมพิกัด GPS รายการแสดงบนหน้าจอพนักงาน |
| **Invariants:** | ประเภทเหตุการณ์ต้องเลือกจากรายการที่เปิดใช้งานเท่านั้น พิกัด GPS ต้องมีค่าเสมอ เบอร์ติดต่อต้องมีค่าเสมอ |
| **Scenarios:** | 1. ผู้แจ้งเหตุกดปุ่ม "แจ้งเหตุ" |
| | 2. ระบบดึงพิกัด GPS ปัจจุบัน (include: ระบุตำแหน่งอัตโนมัติ) |
| | 3. ระบบแสดงแบบฟอร์มแจ้งเหตุ |
| | 4. ผู้แจ้งเหตุเลือกประเภทเหตุการณ์จาก dropdown |
| | 5. ผู้แจ้งเหตุกรอกรายละเอียด (ถ้ามี) |
| | 6. ผู้แจ้งเหตุกรอกเบอร์ติดต่อ หรือใช้เบอร์จากบัญชี |
| | 7. ผู้แจ้งเหตุแนบหลักฐาน เช่น รูปภาพ วิดีโอ เสียง (ถ้ามี) (extend: แนบหลักฐาน) |
| | 8. ผู้แจ้งเหตุกดปุ่ม "ส่งแจ้งเหตุ" |
| | 9. ระบบบันทึกรายการแจ้งเหตุลงฐานข้อมูล |
| | 10. ระบบแสดงข้อความ "แจ้งเหตุสำเร็จ" |
| **Alternative:** | **กรณีไม่สามารถดึงพิกัด GPS ได้** |
| | 1. ระบบแสดงข้อความแจ้งเตือนว่าไม่สามารถระบุตำแหน่งได้ |
| | 2. ผู้แจ้งเหตุอนุญาต Geolocation และลองใหม่ |
| | **กรณีข้อมูลไม่ถูกต้อง** |
| | 1. ระบบแสดงข้อความแจ้งเตือน |
| | 2. ผู้แจ้งเหตุแก้ไขข้อมูลและลองส่งอีกครั้ง |

## ตารางที่ 5 ติดตามสถานะแจ้งเหตุ (Track Incident Status)

| | |
|:---|:---|
| **Use case name:** | ติดตามสถานะแจ้งเหตุ (Track Incident Status) |
| **Description:** | ผู้แจ้งเหตุสามารถดูสถานะของรายการแจ้งเหตุที่ตนเองสร้างไว้ แบบเรียลไทม์ เช่น รอรับเรื่อง กำลังไปช่วยเหลือ สำเร็จ |
| **Primary Actors:** | ผู้แจ้งเหตุ (Reporter) |
| **Goals:** | ผู้แจ้งเหตุทราบสถานะปัจจุบันของรายการแจ้งเหตุ |
| **Precondition:** | ผู้แจ้งเหตุต้องเข้าสู่ระบบสำเร็จแล้ว มีรายการแจ้งเหตุที่ผู้แจ้งเหตุเป็นผู้สร้าง |
| **Postcondition:** | ผู้แจ้งเหตุเห็นสถานะล่าสุดของรายการแจ้งเหตุ |
| **Invariants:** | ผู้แจ้งเหตุสามารถดูได้เฉพาะรายการที่ตนเองสร้างเท่านั้น |
| **Scenarios:** | 1. ผู้แจ้งเหตุเข้าหน้ารายการแจ้งเหตุ |
| | 2. ระบบแสดงรายการแจ้งเหตุทั้งหมดของผู้แจ้งเหตุ |
| | 3. ผู้แจ้งเหตุเลือกดูรายการที่ต้องการ |
| | 4. ระบบแสดงรายละเอียดและสถานะปัจจุบัน (REPORTED / IN_PROGRESS / COMPLETED / CANCELLED) |
| **Alternative:** | **กรณีไม่มีรายการแจ้งเหตุ** |
| | 1. ระบบแสดงข้อความว่าไม่มีรายการแจ้งเหตุ |

## ตารางที่ 6 แชทในห้องเหตุการณ์ (Chat in Incident Room)

| | |
|:---|:---|
| **Use case name:** | แชทในห้องเหตุการณ์ (Chat in Incident Room) |
| **Description:** | ผู้แจ้งเหตุสามารถสนทนากับทีมพนักงานที่รับงานในห้องแชทเฉพาะเหตุการณ์ โดย 1 รายการแจ้งเหตุ = 1 ห้องแชท สามารถส่งข้อความและไฟล์ภาพได้ |
| **Primary Actors:** | ผู้แจ้งเหตุ (Reporter) |
| **Goals:** | ผู้แจ้งเหตุสามารถสื่อสารกับทีมพนักงานที่กำลังช่วยเหลือได้ |
| **Precondition:** | ผู้แจ้งเหตุต้องเข้าสู่ระบบสำเร็จแล้ว มีรายการแจ้งเหตุที่มีทีมรับงานแล้ว |
| **Postcondition:** | ข้อความและไฟล์แนบถูกบันทึกในฐานข้อมูลและแสดงแก่ผู้ที่อยู่ในห้องแชท |
| **Invariants:** | ผู้แจ้งเหตุสามารถแชทได้เฉพาะในห้องเหตุการณ์ที่ตนเองเป็นผู้สร้างเท่านั้น |
| **Scenarios:** | 1. ผู้แจ้งเหตุเข้าดูรายการแจ้งเหตุที่มีทีมรับงานแล้ว |
| | 2. ผู้แจ้งเหตุกดเปิดห้องแชท |
| | 3. ระบบแสดงข้อความเก่าทั้งหมดในห้องแชท |
| | 4. ผู้แจ้งเหตุพิมพ์ข้อความหรือแนบรูปภาพ |
| | 5. ผู้แจ้งเหตุกดปุ่ม "ส่ง" |
| | 6. ระบบบันทึกข้อความลงฐานข้อมูลและแสดงในห้องแชท |
| **Alternative:** | **กรณีส่งข้อความล้มเหลว** |
| | 1. ระบบแสดงข้อความแจ้งเตือนว่าส่งไม่สำเร็จ |
| | 2. ผู้แจ้งเหตุลองส่งใหม่ |

## ตารางที่ 7 รายงานพฤติกรรมพนักงาน (Report Staff Behavior)

| | |
|:---|:---|
| **Use case name:** | รายงานพฤติกรรมพนักงาน (Report Staff Behavior) |
| **Description:** | ผู้แจ้งเหตุสามารถรายงานพฤติกรรมที่ไม่เหมาะสมของพนักงาน เพื่อส่งให้ผู้ดูแลระบบตรวจสอบ |
| **Primary Actors:** | ผู้แจ้งเหตุ (Reporter) |
| **Goals:** | รายงานถูกส่งไปยังผู้ดูแลระบบเพื่อตรวจสอบ |
| **Precondition:** | ผู้แจ้งเหตุต้องเข้าสู่ระบบสำเร็จแล้ว มีเหตุการณ์ที่เกี่ยวข้องกับพนักงานที่ต้องการรายงาน |
| **Postcondition:** | รายงานถูกสร้างในระบบ สถานะ = PENDING รอผู้ดูแลระบบตรวจสอบ |
| **Invariants:** | ต้องระบุสาเหตุการรายงานเสมอ |
| **Scenarios:** | 1. ผู้แจ้งเหตุเลือกรายงานพนักงาน |
| | 2. ระบบแสดงแบบฟอร์มรายงาน |
| | 3. ผู้แจ้งเหตุเลือกพนักงานที่ต้องการรายงาน |
| | 4. ผู้แจ้งเหตุกรอกสาเหตุและเหตุการณ์ที่เกี่ยวข้อง |
| | 5. ผู้แจ้งเหตุกดปุ่ม "ส่งรายงาน" |
| | 6. ระบบบันทึกรายงานลงฐานข้อมูล |
| | 7. ระบบแสดงข้อความ "ส่งรายงานสำเร็จ" |
| **Alternative:** | **กรณีไม่กรอกสาเหตุ** |
| | 1. ระบบแสดงข้อความแจ้งเตือนว่าต้องกรอกสาเหตุ |
| | 2. ผู้แจ้งเหตุกรอกสาเหตุและส่งใหม่ |
