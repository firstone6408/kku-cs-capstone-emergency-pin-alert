# Use Case Description — พนักงาน/อาสา (Staff / Volunteer)

---

## ตารางที่ 1 เข้าสู่ระบบ (Login)

| | |
|:---|:---|
| **Use case name:** | เข้าสู่ระบบ (Login) |
| **Description:** | พนักงานหรืออาสาสามารถเข้าสู่ระบบด้วยอีเมลและรหัสผ่าน เพื่อใช้งานฟีเจอร์ดูรายการแจ้งเหตุ จัดการทีม และรับงานช่วยเหลือ |
| **Primary Actors:** | พนักงาน/อาสา (Staff / Volunteer) |
| **Goals:** | พนักงานเข้าสู่ระบบสำเร็จและสามารถใช้งานระบบได้ |
| **Precondition:** | พนักงานมีบัญชีในระบบ บัญชีไม่ถูกระงับ (Block) ระบบพร้อมใช้งาน |
| **Postcondition:** | พนักงานได้รับ JWT Token และเข้าสู่หน้าหลักของพนักงาน |
| **Invariants:** | รหัสผ่านต้องตรงกับที่เข้ารหัสไว้ในฐานข้อมูล Token ถูกเก็บใน httpOnly Cookie |
| **Scenarios:** | 1. พนักงานเปิดหน้าเข้าสู่ระบบ |
| | 2. ระบบแสดงแบบฟอร์มเข้าสู่ระบบ |
| | 3. พนักงานกรอกอีเมลและรหัสผ่าน |
| | 4. พนักงานกดปุ่ม "เข้าสู่ระบบ" |
| | 5. ระบบตรวจสอบอีเมลและรหัสผ่าน |
| | 6. ระบบสร้าง JWT Token และเก็บใน Cookie |
| | 7. ระบบแสดงหน้าหลักของพนักงาน |
| **Alternative:** | **กรณีอีเมลหรือรหัสผ่านไม่ถูกต้อง** |
| | 1. ระบบแสดงข้อความแจ้งเตือนว่าข้อมูลไม่ถูกต้อง |
| | 2. พนักงานกรอกข้อมูลใหม่ |
| | **กรณีบัญชีถูกระงับ** |
| | 1. ระบบแสดงข้อความว่าบัญชีถูกระงับ |
| | 2. พนักงานไม่สามารถเข้าสู่ระบบได้ |

## ตารางที่ 2 จัดการข้อมูลส่วนตัว (Manage Profile)

| | |
|:---|:---|
| **Use case name:** | จัดการข้อมูลส่วนตัว (Manage Profile) |
| **Description:** | พนักงานสามารถแก้ไขข้อมูลส่วนตัวได้ เช่น ชื่อ-นามสกุล เบอร์โทร บทบาท (อาสา/เจ้าหน้าที่) และรหัสผ่าน |
| **Primary Actors:** | พนักงาน/อาสา (Staff / Volunteer) |
| **Goals:** | การแก้ไขข้อมูลส่วนตัวสามารถแก้ไขได้ตามความต้องการของพนักงาน |
| **Precondition:** | พนักงานต้องเข้าสู่ระบบสำเร็จแล้ว ระบบฐานข้อมูลต้องพร้อมใช้งาน |
| **Postcondition:** | ข้อมูลส่วนตัวของพนักงานถูกอัปเดตในฐานข้อมูล ระบบแสดงข้อมูลที่แก้ไขแล้วอย่างถูกต้อง |
| **Invariants:** | อีเมลต้องไม่เปลี่ยนแปลง รูปแบบข้อมูลต้องถูกต้องเสมอ พนักงานสามารถแก้ไขได้เฉพาะข้อมูลของตนเองเท่านั้น |
| **Scenarios:** | 1. พนักงานเข้าสู่ระบบ |
| | 2. พนักงานเลือกเมนู "ข้อมูลส่วนตัว" |
| | 3. ระบบแสดงข้อมูลปัจจุบันในแบบฟอร์ม |
| | 4. พนักงานแก้ไขข้อมูลที่ต้องการ |
| | 5. พนักงานกดปุ่ม "บันทึก" |
| | 6. ระบบบันทึกข้อมูลลงฐานข้อมูล |
| | 7. ระบบแสดงข้อความ "อัปเดตข้อมูลสำเร็จ" |
| **Alternative:** | **กรณีข้อมูลไม่ถูกต้อง** |
| | 1. หากกรอกข้อมูลผิดรูปแบบหรือไม่ครบ |
| | 2. ระบบแสดงข้อความแจ้งเตือน |
| | 3. พนักงานแก้ไขข้อมูล |
| | 4. ระบบกลับไปขั้นตอนการบันทึกใหม่ |

## ตารางที่ 3 ดูรายการแจ้งเหตุ (View Incident List)

| | |
|:---|:---|
| **Use case name:** | ดูรายการแจ้งเหตุ (View Incident List) |
| **Description:** | พนักงานสามารถดูรายการแจ้งเหตุฉุกเฉินทั้งหมดที่ส่งเข้ามาในระบบ โดยเรียงลำดับตามระดับความสำคัญของประเภทเหตุการณ์ จากสำคัญสุดไปน้อยสุด |
| **Primary Actors:** | พนักงาน/อาสา (Staff / Volunteer) |
| **Goals:** | พนักงานเห็นรายการแจ้งเหตุทั้งหมดเรียงตามลำดับความสำคัญ เพื่อตัดสินใจรับงาน |
| **Precondition:** | พนักงานต้องเข้าสู่ระบบสำเร็จแล้ว |
| **Postcondition:** | พนักงานเห็นรายการแจ้งเหตุพร้อมรายละเอียด ประเภท สถานะ และตำแหน่งบนแผนที่ |
| **Invariants:** | รายการต้องเรียงตามระดับความสำคัญเสมอ |
| **Scenarios:** | 1. พนักงานเข้าสู่ระบบ |
| | 2. พนักงานเลือกเมนู "รายการแจ้งเหตุ" |
| | 3. ระบบดึงรายการแจ้งเหตุจากฐานข้อมูล |
| | 4. ระบบเรียงลำดับตาม priority_level ของประเภทเหตุการณ์ |
| | 5. ระบบแสดงรายการแจ้งเหตุพร้อมข้อมูล ประเภท สถานะ เบอร์ติดต่อ และตำแหน่ง |
| **Alternative:** | **กรณีไม่มีรายการแจ้งเหตุ** |
| | 1. ระบบแสดงข้อความว่าไม่มีรายการแจ้งเหตุในขณะนี้ |

## ตารางที่ 4 จัดการทีม (Manage Team)

| | |
|:---|:---|
| **Use case name:** | จัดการทีม (Manage Team) |
| **Description:** | พนักงานสามารถสร้างทีม สังกัดทีม ย้ายทีม หรือออกจากทีมได้ โดยทีมใช้สำหรับไปช่วยเหลือเหตุฉุกเฉินเป็นกลุ่ม ทีมหนึ่งมีสมาชิกได้ตั้งแต่ 1 คนขึ้นไป |
| **Primary Actors:** | พนักงาน/อาสา (Staff / Volunteer) |
| **Goals:** | พนักงานสามารถจัดการทีมของตนเองได้อย่างยืดหยุ่น |
| **Precondition:** | พนักงานต้องเข้าสู่ระบบสำเร็จแล้ว |
| **Postcondition:** | ข้อมูลการสังกัดทีมถูกอัปเดตในฐานข้อมูล |
| **Invariants:** | พนักงาน 1 คน สังกัดได้ 1 ทีม ณ เวลาใดเวลาหนึ่ง เมื่อย้ายทีม ระบบจะบันทึก left_at ของทีมเก่าและสร้างรายการใหม่ในทีมใหม่ |
| **Scenarios:** | 1. พนักงานเข้าสู่ระบบ |
| | 2. พนักงานเลือกเมนู "จัดการทีม" |
| | 3. ระบบแสดงทีมปัจจุบันและรายชื่อทีมทั้งหมด |
| | 4. พนักงานเลือกดำเนินการ (สร้างทีม / เข้าร่วมทีม / ย้ายทีม / ออกจากทีม) |
| | 5. ระบบบันทึกการเปลี่ยนแปลงลงฐานข้อมูล |
| | 6. ระบบแสดงข้อมูลทีมที่อัปเดตแล้ว |
| **Alternative:** | **กรณีทีมกำลังทำภารกิจ** |
| | 1. หากทีมที่สังกัดอยู่มีสถานะ ON_MISSION |
| | 2. พนักงานไม่สามารถย้ายหรือออกจากทีมได้จนกว่าภารกิจจะเสร็จสิ้น |

## ตารางที่ 5 รับงานแจ้งเหตุ (Accept Incident)

| | |
|:---|:---|
| **Use case name:** | รับงานแจ้งเหตุ (Accept Incident) |
| **Description:** | พนักงานสามารถกดรับงานแจ้งเหตุ ระบบจะเปลี่ยนสถานะทีมเป็น ON_MISSION และส่งการแจ้งเตือนไปยังผู้แจ้งเหตุ |
| **Primary Actors:** | พนักงาน/อาสา (Staff / Volunteer) |
| **Goals:** | ทีมรับงานสำเร็จ ระบบเปลี่ยนสถานะและแจ้งเตือนผู้แจ้งเหตุ |
| **Precondition:** | พนักงานต้องมีทีมที่สังกัด ทีมมีสถานะ AVAILABLE รายการมีสถานะ REPORTED หรือ NEED_MORE_TEAMS จำนวนทีมที่รับงานต้องไม่เกิน max_teams |
| **Postcondition:** | สถานะทีม = ON_MISSION สถานะรายการ = IN_PROGRESS ระบบ snapshot สมาชิกทีมในตาราง incident_assignment_members |
| **Invariants:** | ทีมที่สถานะ ON_MISSION ไม่สามารถรับงานอื่นได้ รายการที่ทีมครบ max_teams แล้ว ทีมอื่นไม่สามารถรับงานเพิ่มได้ |
| **Scenarios:** | 1. พนักงานดูรายการแจ้งเหตุ |
| | 2. พนักงานเลือกรายการที่ต้องการรับงาน |
| | 3. พนักงานกดปุ่ม "รับงาน" |
| | 4. ระบบตรวจสอบสถานะทีมและรายการ |
| | 5. ระบบเปลี่ยนสถานะทีมเป็น ON_MISSION |
| | 6. ระบบเปลี่ยนสถานะรายการเป็น IN_PROGRESS |
| | 7. ระบบ snapshot สมาชิกทีมทั้งหมดลงตาราง incident_assignment_members |
| | 8. ระบบแจ้งเตือนผู้แจ้งเหตุว่ามีทีมรับงานแล้ว |
| | 9. ระบบแสดงตำแหน่งจุดเกิดเหตุบนแผนที่ (include: นำทางไปจุดเกิดเหตุ) |
| **Alternative:** | **กรณีทีมไม่ว่าง** |
| | 1. หากทีมมีสถานะ ON_MISSION ระบบแสดงข้อความว่าทีมกำลังทำภารกิจอยู่ |
| | **กรณีรายการเต็มแล้ว** |
| | 1. หากจำนวนทีมครบ max_teams แล้ว ระบบแสดงข้อความว่ารายการมีทีมรับงานครบแล้ว |

## ตารางที่ 6 ขอทีมสนับสนุน (Request Backup Team)

| | |
|:---|:---|
| **Use case name:** | ขอทีมสนับสนุน (Request Backup Team) |
| **Description:** | กรณีที่พนักงานประเมินว่าทีมไม่เพียงพอ สามารถกดร้องขอทีมสนับสนุนเพิ่มเติม ระบบจะเพิ่ม max_teams และเปิดให้ทีมอื่นรับงานเพิ่ม |
| **Primary Actors:** | พนักงาน/อาสา (Staff / Volunteer) |
| **Goals:** | ระบบเปิดรับทีมเพิ่มเติมเพื่อให้มีกำลังคนเพียงพอ |
| **Precondition:** | พนักงานต้องเป็นทีมที่กำลังทำภารกิจรายการนั้นอยู่ (ON_MISSION) |
| **Postcondition:** | สถานะรายการ = NEED_MORE_TEAMS ค่า max_teams เพิ่มขึ้น ทีมอื่นสามารถกดรับงานได้ |
| **Invariants:** | ต้องเป็นทีมที่รับงานรายการนั้นอยู่เท่านั้นจึงจะขอทีมเพิ่มได้ |
| **Scenarios:** | 1. ทีมพนักงานกำลังทำภารกิจ |
| | 2. พนักงานประเมินว่าทีมไม่เพียงพอ |
| | 3. พนักงานกดปุ่ม "ขอทีมเพิ่ม" |
| | 4. ระบบเปลี่ยนสถานะรายการเป็น NEED_MORE_TEAMS |
| | 5. ระบบเพิ่มค่า max_teams |
| | 6. ทีมอื่นสามารถเห็นและกดรับงานรายการนี้ได้ |
| **Alternative:** | ไม่มี |

## ตารางที่ 7 นำทางไปจุดเกิดเหตุ (Navigate to Incident Location)

| | |
|:---|:---|
| **Use case name:** | นำทางไปจุดเกิดเหตุ (Navigate to Incident Location) |
| **Description:** | ระบบแสดงพิกัดจุดเกิดเหตุบนแผนที่และสามารถเชื่อมโยงระบบนำทางไปยังจุดเกิดเหตุได้ |
| **Primary Actors:** | พนักงาน/อาสา (Staff / Volunteer) |
| **Goals:** | พนักงานเดินทางไปถึงจุดเกิดเหตุได้อย่างรวดเร็วและถูกต้อง |
| **Precondition:** | พนักงานต้องรับงานรายการแจ้งเหตุแล้ว รายการมีพิกัด GPS |
| **Postcondition:** | พนักงานเห็นตำแหน่งจุดเกิดเหตุบนแผนที่และสามารถใช้ระบบนำทาง |
| **Invariants:** | พิกัด GPS ของรายการแจ้งเหตุต้องมีค่าเสมอ |
| **Scenarios:** | 1. พนักงานรับงานรายการแจ้งเหตุ |
| | 2. ระบบแสดงตำแหน่งจุดเกิดเหตุเป็นหมุดบนแผนที่ |
| | 3. พนักงานกดปุ่ม "นำทาง" |
| | 4. ระบบเปิด Google Maps พร้อมพิกัดปลายทาง |
| | 5. พนักงานเดินทางตามเส้นทาง |
| **Alternative:** | **กรณีแผนที่โหลดไม่สำเร็จ** |
| | 1. ระบบแสดงพิกัดเป็นข้อความ (Latitude, Longitude) |
| | 2. พนักงานคัดลอกพิกัดไปใช้ในแอปนำทางเอง |

## ตารางที่ 8 สิ้นสุดภารกิจ (Complete Mission)

| | |
|:---|:---|
| **Use case name:** | สิ้นสุดภารกิจ (Complete Mission) |
| **Description:** | เมื่อปฏิบัติภารกิจช่วยเหลือเสร็จสิ้น พนักงานกดปุ่มสิ้นสุดภารกิจ ระบบเปลี่ยนสถานะทีมกลับเป็นว่างและอัปเดตสถานะรายการ |
| **Primary Actors:** | พนักงาน/อาสา (Staff / Volunteer) |
| **Goals:** | ภารกิจเสร็จสิ้น ทีมกลับมาพร้อมรับงานใหม่ |
| **Precondition:** | ทีมมีสถานะ ON_MISSION ทีมกำลังปฏิบัติงานในรายการแจ้งเหตุ |
| **Postcondition:** | สถานะทีม = AVAILABLE สถานะมอบหมาย = COMPLETED สถานะรายการ = COMPLETED (หากทุกทีมทำเสร็จ) |
| **Invariants:** | ทีมที่สถานะ AVAILABLE ไม่สามารถกดสิ้นสุดภารกิจได้ |
| **Scenarios:** | 1. ทีมพนักงานช่วยเหลือเหตุฉุกเฉินเสร็จสิ้น |
| | 2. พนักงานกดปุ่ม "สิ้นสุดภารกิจ" |
| | 3. ระบบเปลี่ยนสถานะทีมเป็น AVAILABLE |
| | 4. ระบบเปลี่ยนสถานะการมอบหมายเป็น COMPLETED พร้อมบันทึกเวลา |
| | 5. ระบบตรวจสอบว่าทุกทีมทำเสร็จหรือยัง |
| | 6. ถ้าทุกทีมเสร็จ ระบบเปลี่ยนสถานะรายการเป็น COMPLETED |
| | 7. ระบบแจ้งเตือนผู้แจ้งเหตุว่าภารกิจเสร็จสิ้น |
| **Alternative:** | ไม่มี |

## ตารางที่ 9 แชทในห้องเหตุการณ์ (Chat in Incident Room)

| | |
|:---|:---|
| **Use case name:** | แชทในห้องเหตุการณ์ (Chat in Incident Room) |
| **Description:** | พนักงานสามารถสนทนากับผู้แจ้งเหตุและทีมสนับสนุนอื่นๆ ในห้องแชทเฉพาะเหตุการณ์ ทุกคนในทุกทีมที่รับงาน + ผู้แจ้งเหตุ สามารถส่งข้อความและไฟล์ได้ |
| **Primary Actors:** | พนักงาน/อาสา (Staff / Volunteer) |
| **Goals:** | พนักงานสามารถสื่อสารกับผู้แจ้งเหตุและทีมอื่นที่ร่วมภารกิจเดียวกันได้ |
| **Precondition:** | พนักงานต้องเข้าสู่ระบบสำเร็จแล้ว ทีมของพนักงานรับงานรายการนั้นอยู่ |
| **Postcondition:** | ข้อความและไฟล์แนบถูกบันทึกในฐานข้อมูลและแสดงแก่ผู้ที่อยู่ในห้องแชท |
| **Invariants:** | พนักงานสามารถแชทได้เฉพาะในห้องเหตุการณ์ที่ทีมของตนรับงานอยู่เท่านั้น |
| **Scenarios:** | 1. พนักงานเปิดรายการแจ้งเหตุที่ทีมรับงานอยู่ |
| | 2. พนักงานกดเปิดห้องแชท |
| | 3. ระบบแสดงข้อความเก่าทั้งหมดในห้องแชท |
| | 4. พนักงานพิมพ์ข้อความหรือแนบรูปภาพ |
| | 5. พนักงานกดปุ่ม "ส่ง" |
| | 6. ระบบบันทึกข้อความและแสดงในห้องแชท |
| **Alternative:** | **กรณีส่งข้อความล้มเหลว** |
| | 1. ระบบแสดงข้อความแจ้งเตือนว่าส่งไม่สำเร็จ |
| | 2. พนักงานลองส่งใหม่ |

## ตารางที่ 10 รายงานพฤติกรรมผู้ใช้ (Report User Behavior)

| | |
|:---|:---|
| **Use case name:** | รายงานพฤติกรรมผู้ใช้ (Report User Behavior) |
| **Description:** | พนักงานสามารถรายงานพฤติกรรมที่ไม่เหมาะสมของผู้แจ้งเหตุ (เช่น แจ้งเหตุเท็จ) หรือพนักงานคนอื่น เพื่อส่งให้ผู้ดูแลระบบตรวจสอบ |
| **Primary Actors:** | พนักงาน/อาสา (Staff / Volunteer) |
| **Goals:** | รายงานถูกส่งไปยังผู้ดูแลระบบเพื่อตรวจสอบ |
| **Precondition:** | พนักงานต้องเข้าสู่ระบบสำเร็จแล้ว |
| **Postcondition:** | รายงานถูกสร้างในระบบ สถานะ = PENDING รอผู้ดูแลระบบตรวจสอบ |
| **Invariants:** | ต้องระบุสาเหตุการรายงานเสมอ |
| **Scenarios:** | 1. พนักงานเลือกรายงานผู้ใช้ |
| | 2. ระบบแสดงแบบฟอร์มรายงาน |
| | 3. พนักงานเลือกผู้ใช้ที่ต้องการรายงาน |
| | 4. พนักงานกรอกสาเหตุและเหตุการณ์ที่เกี่ยวข้อง (ถ้ามี) |
| | 5. พนักงานกดปุ่ม "ส่งรายงาน" |
| | 6. ระบบบันทึกรายงานลงฐานข้อมูล |
| | 7. ระบบแสดงข้อความ "ส่งรายงานสำเร็จ" |
| **Alternative:** | **กรณีไม่กรอกสาเหตุ** |
| | 1. ระบบแสดงข้อความแจ้งเตือนว่าต้องกรอกสาเหตุ |
| | 2. พนักงานกรอกสาเหตุและส่งใหม่ |
